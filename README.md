# GM Kit

Локальные инструменты мастера для настольных систем: **PWA для стола**, **CLI** и
**LAN-режим для игроков**. Сейчас поддерживаются **Pathfinder 2e** и **D&D 5e (2014)**.
Правила, бестиарий и бои хранятся в браузере (IndexedDB) и никуда не отправляются.

- Тёмный интерфейс, русский и английский языки.
- Мастер работает на `localhost`, игроки подключаются по локальной сети.
- Игроки видят правила и очередь ходов, но **не видят HP, AC и журнал боя**.
- Без нативных модулей: Windows, macOS, Linux.

## Возможности

| Раздел | Что делает |
| --- | --- |
| **Правила** | BM25-поиск, встроенные карточки, импорт, фильтры, ссылки на источники |
| **Энкаунтеры** | PF2e: XP-бюджет; D&D 5e: пороги DMG 2014, CR, множители |
| **Бой** | Инициатива, раунды, HP/AC, состояния; PF2e: MAP и dying; D&D: advantage, concentration, death saves |
| **Заготовки** | Сохранение состава боя и запуск новой копии одним кликом |
| **Инициатива** | Ручное изменение инициативы в инспекторе бойца с пересортировкой очереди |
| **Настройки** | Импорт, резервные копии, LAN-адрес, постоянное хранилище |
| **LAN** | Игроки открывают ссылку в браузере и видят очередь ходов и правила мастера |

Горячие клавиши: `Ctrl/⌘ + K` — палитра и поиск правил, `Ctrl/⌘ + 1…4` — разделы.

## Быстрый старт

Нужен **Node.js 20+**.

### Windows

Дважды щёлкни `start-win.cmd`. При первом запуске он поставит зависимости,
соберёт PWA и откроет `http://localhost:4173`. Окно консоли должно оставаться
открытым; остановка — `Ctrl+C`.

Если Windows SmartScreen предупреждает: «Подробнее» → «Выполнить в любом случае».

### macOS

Один раз в терминале:

```bash
chmod +x start-mac.command dev-mac.command
```

Затем двойной клик по `start-mac.command`. Если система блокирует — правый клик →
«Открыть».

### Linux

```bash
npm install
npm run build:all
npm start
```

### Проверка

```bash
npm run doctor
```

## Игроки в локальной сети

1. Мастер запускает `start-win.cmd` или `start-mac.command`.
2. В консоли появляются адреса, например:

```text
Мастер:  http://localhost:4173
Игроки:  http://<LAN-IP>:4173
```

3. Игроки открывают LAN-адрес в браузере или сканируют QR из настроек. Установка не требуется.
4. Мастер ведёт бой как обычно — игроки видят раунд, очередь инициативы и
   подсветку «Ходит».
5. Импортированные правила автоматически публикуются игрокам. Их можно найти
   во вкладке «Правила».

Важно:

- HP, AC, состояния и журнал боя игрокам не передаются.
- Тумблер **«Игроки»** в шапке боя скрывает или возвращает трансляцию.
- Кнопка **«Окончить бой»** останавливает бой, сохраняя состав и журнал; игроки видят «Бой окончен».
- Кнопка **«В заготовки»** сохраняет состав, **«Заготовки»** — загружает его в новый бой.
- Инициативу можно изменить вручную в инспекторе бойца.
- В настройках показывается основная LAN-ссылка с QR-кодом; остальные сети свёрнуты.
- Windows спросит доступ к сети — разреши **частные сети**.
- Гостевая Wi-Fi-сеть с изоляцией клиентов не подойдёт.
- На LAN-адресе нет HTTPS, поэтому установка PWA на телефоны недоступна —
  игроки работают во вкладке браузера. Это нормально для стола.
- Если открыть LAN-адрес на машине мастера, включится режим игрока. Для
  управления используй `localhost`.

## Данные и импорт

У каждой системы своё хранилище: правила, бестиарий и бои не смешиваются.
Система переключается в сайдбаре.

### Встроенные данные

- **PF2e:** 40 карточек правил и 12 демо-существ.
- **D&D 5e (2014):** стартовые SRD-карточки и примеры монстров со ссылками на
  D&D Beyond. Это краткие пересказы, а не замена книгам.

### Импорт JSON

Настройки → **Импортировать JSON из CLI** (или обычный JSON) → выбери файлы.

Поддерживаются:

- массив правил;
- массив монстров;
- объект `{ rules, monsters }`;
- для D&D CR можно указывать строкой: `"1/8"`, `"1/4"`, `"1/2"`, `"5"`.

Данные записываются в активную систему.

### Foundry

Для PF2e остаётся импорт папки `packs` системы `pf2e` и CLI-скрипт:

```bash
npm run import:foundry -- "/path/to/FoundryVTT/Data/systems/pf2e/packs"
```

Для D&D Foundry не требуется: достаточно встроенного набора и JSON-импорта.

### Готовый конфиг напоминалок

`configs/pf2e-reminders.json` — 113 карточек из личной напоминалки:
24 действия, 31 состояние, 17 навыков и 41 бог.

Импорт: Настройки → **Импортировать JSON из CLI** → выбрать файл.
Карточки попадут в поиск правил с категориями «Действия», «Состояния»,
«Навыки» и «Боги».

### Резервные копии

- **Экспорт** — один JSON со всеми системами: правилами, монстрами, боями и заготовками.
- **Импорт** — заменяет локальные данные содержимым файла.
- Старые бэкапы PF2e импортируются автоматически.
- Кнопка **«Запросить постоянное хранилище»** снижает риск очистки IndexedDB.

## D&D 5e (2014)

### Энкаунтеры

- XP-пороги easy/medium/hard/deadly на персонажа;
- бюджет = порог × размер партии;
- XP по CR;
- множитель за количество монстров (×1 … ×4);
- поправка для партии меньше 3 или больше 5;
- предупреждения о слишком высоком CR и одиночном боссе.

### Бой

- инициатива `d20 + DEX`;
- HP, temp HP, AC;
- action / bonus action / reaction;
- состояния и exhaustion 1–6;
- **advantage / disadvantage**: два d20, взаимное гашение, журнал;
- **concentration**: название заклинания, DC 10 или половина урона, ручное
  подтверждение провала;
- **death saves**: успехи/провалы, натуральная 1 и 20, стабилизация;
- раунды и текущий ход.

## PF2e

- XP-бюджет 10/15/20/30/40 за персонажа;
- DP-подбор состава, предупреждения;
- 3 действия, MAP, quickened/slowed/stunned;
- dying/wounded/doomed, recovery check, persistent damage;
- resistance/weakness/immunity и temp HP.

## CLI

CLI использует ядро PF2e:

```bash
npm run build
node dist/cli/index.js --help

npm run dev:cli -- rules "grapple"
pf rules "dying" --limit 3
pf encounter --level 5 --party 4 --difficulty severe
pf combat add "Ария" --pc --hp 44 --ac 21 --level 5 --init 15
pf combat start
pf combat next
```

Глобальная команда:

```bash
npm link
pf --help
```

## Разработка

```bash
npm install
npm run dev          # Vite: http://localhost:5173
npm run dev:cli      # CLI через tsx
npm run typecheck
npm test             # 68 тестов
npm run check:i18n
npm run build:all    # CLI (dist) + PWA (dist-web)
npm run verify
```

Dev-сервер не поддерживает LAN API. Для проверки игроков используй
`start-win.cmd` / `start-mac.command`.

Структура:

```text
src/core/                  поиск, RNG, общие типы
src/systems/types.ts       реестр систем
src/systems/live.ts        безопасный снимок боя для игроков
src/systems/dnd5e/         энкаунтеры и бой D&D 5e 2014
src/cli/                   CLI PF2e
src/web/                   React 19 + Vite + Dexie
  PlayerApp.tsx            режим игрока
  live.ts                  SSE, публикация боя и правил
  features/dnd/            экраны D&D
scripts/start.mjs          локальный сервер + LAN API
data/dnd5e/                встроенные правила и монстры D&D
data/rules, data/monsters  встроенные данные PF2e
test/                      vitest
```

Стек: Vite 7, React 19, TypeScript, Tailwind CSS 4, Dexie 4, zustand,
i18next, cmdk, lucide-react, vite-plugin-pwa, SSE.

## Ограничения и планы

- Пользовательские декларативные системы — следующий этап.
- Импорт Foundry `dnd5e` не входит в текущую версию; используется JSON и SRD.
- Нет синхронизации данных между устройствами — только бэкап.
- LAN-игроки работают без установки PWA (HTTP, не HTTPS).
- Экспорт энкаунтера в Foundry, конспект кампании, локальная LLM — в планах.
